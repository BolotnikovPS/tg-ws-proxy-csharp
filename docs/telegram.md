# Настройка Telegram

[← Оглавление](README.md)

Самый простой путь — панель, раздел **«Токены доступа»**: у каждого токена своя ссылка, кнопка **«Ссылка MTProto»** копирует готовую конфигурацию для Telegram в буфер обмена. Секрет показывается при создании, при ротации и подставляется в поле при редактировании. Внешний адрес задаётся ключом `publicHost` (раздел панели «Ссылки Telegram»): слушатель всегда привязан ко всем интерфейсам и внешний адрес подставить невозможно, поэтому без `publicHost` ссылка не строится — укажите домен или публичный IP вместе с опубликованным портом, например `proxy.example.com:1443`.

Формат ссылки зависит от режима:

- `tg://proxy?server=...&port=...&secret=dd<secret>` — обычный режим;
- `tg://proxy?server=...&port=...&secret=ee<secret><hex(домен)>` — если задан `fakeTlsDomain` (маскировка под HTTPS к указанному домену).

## Telegram Desktop

1. **Настройки → Продвинутые настройки → Тип подключения → Прокси**.
2. Добавьте прокси типа **MTProto**:
   - Сервер: `127.0.0.1` (или адрес сервера);
   - Порт: `1443` (или ваш `port`);
   - Секрет: `dd…` или `ee…` нужного токена.

## Telegram Mobile

Нажмите ссылку `tg://proxy?...` из панели или лога — Telegram сам предложит добавить прокси.

## WEB proxy

Отдельная кнопка панели — **«Ссылка Web»** — копирует ссылку-приглашение по каноническому шаблону Telegram:

```
https://t.me/webproxy?server=<host>[/<basePath>]&secret=<secret>
```

- `server` — внешний домен (`webProxy.publicHost`); при заданном `webProxy.basePath` путь дописывается через `/` и percent-кодируется целиком (`proxy.example.com%2Fv1`). Порт в ссылке не участвует: HTTPS и 443 зафиксированы самим типом прокси.
- `secret` — тот же секрет, что и у MTProxy: обычные 32 hex для корня (`webProxy.basePath` пуст) и `base64url(0x70 ‖ secret)` без паддинга при заданном base path. Немаркированный секрет на ссылке с путём клиент отвергает.
- Эквивалентный deep-link `tg://webproxy?server=…&secret=…` открывается сразу в клиенте, минуя сайт t.me (публичный маршрут `t.me/webproxy` пока не зарегистрирован). Панель показывает его в статусе после копирования.

Ограничения адреса: **только домен** — IP-адреса (`127.0.0.1`, `127.1`, `0x7f.1`) и хосты без точки (`localhost`) Telegram не принимает, поэтому при таком `webProxy.publicHost` ссылка не строится. IDN приводится к ACE-форме (`bücher.example` → `xn--bcher-kva.example`), регистр понижается.

Bridge-URL `https://<host>/<basePath>/?bridge=<capability>` — это адрес страницы-носителя с HMAC-capability, он нужен для отладки и смоук-клиента и **не является** ссылкой для Telegram. Настройка и проверка — в разделе [Конфигурация → WEB proxy](configuration.md#web-proxy-browser-relay-bridge).
